Selected technical decisions

Isolation in the database, not only in code

Every query goes through PostgreSQL policies tied to the user's organization. A bug in the application is not enough to expose another customer's data.

Big changes without affecting real users

The multi-tenant migration was done in small steps, each checked against the previous behavior, while the assistant kept serving customers.

Controlled AI cost

Prompt caching, per-customer token metering and a cap included in the plan, so the margin does not depend on usage.

How I work with AI coding agents

Context and scope before asking for code

Every large change starts with a written scope and business rules, and moves in small steps with a verifiable goal. That is how I did the multi-tenant migration in six steps with zero downtime.

I do not take the AI's word for it

A caching change made with the agent looked fine, but in production the dashboard started logging people out. The cause: it cached database failures. I reverted it and set the rule that an error is never cached.

Verification with evidence

Automated tests against real behavior: 39 tenant-isolation checks, end-to-end conversation scripts for the assistant and large-scale comparisons against the previous version before each release.
